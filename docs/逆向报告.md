# PairVPN 1.8.51 (com.pairvpn) 逆向报告

> 样本：`PairVPN com.pairvpn v1.8.51 b1851.apk`（versionCode 1851，1047 个文件，约 11.6 MB 压缩 / 25.4 MB 解包）
> 渠道：ElaMods 破解版（`Application` = `bin.mt.signature.elamods`，内含 `E_l_a_Mods.xml`、`assets/Modder_Hub_*`、`lib/arm64-v8a/El-a Mo-ds.so`），另叠加第三方推广壳
> 工作目录：`Desktop/逆向产物/PairVPN_1.8.51/`

---

## 0. 一句话结论

**PairVPN 不是商业机场，是「设备对设备」(P2P) 的 VPN 工具。** 客户端只能连「你自己配对过的另一台设备」，服务端跑在用户自己的手机/电脑上。地址服务器 `pairv.net` 只负责发放会话令牌与 ICE 地址，**不下发任何服务器列表**。

⇒ **可收割出口节点数 = 0，无法为代理池供血。** 详见 `POOL_VERDICT.md`。

## 1. 样本结构

| 组件 | 说明 |
| --- | --- |
| `classes.dex` (9.1 MB) | 绝大部分是 SDK（Firebase / Play Services / AppCompat / WebView） |
| `classes2.dex` (1.57 MB) / `classes3.dex` (54 KB) | Kotlin 协程 + `ApkSignatureKillerEx` 反签名校验壳 |
| `lib/<abi>/libnative-lib.so` (1.6 MB) | **真正的业务内核**，C++ 编写，保留完整 mangled 符号（无 strip） |
| `assets/html/main.html` + `main.js` | **UI 就是网页**，由 WebView 渲染，native 通过 `uiCallJS()` 注入状态 |
| `assets/html/bootstrap|jquery` | Bootstrap 3.3.7 / jQuery 3.5.1 |

业务 Java 类只有 12 个，全是薄壳：

```
com.pairvpn.MainActivity                  WebView 宿主
com.pairvpn.Platform                      JNI 桥（platformInitNative / getUrlResponse /
                                          platformVpn* / getModeNative / onJsCallback …）
com.pairvpn.MyUtils                       getSslUrl() = HttpURLConnection GET 裸请求
com.pairvpn.MyBase64                      UI 与 native 之间的参数编码
com.pairvpn.client.MyVpnService           VpnService（客户端侧 tun）
com.pairvpn.server.MyService              前台服务（服务端侧常驻）
com.pairvpn.server.MyFirebaseMessagingService / MyReceiver   推送与广播
```

**结论：这不是一个「有服务器列表的 App」，架构上就没有「节点」这个概念。**

## 2. 双模架构

UI（`main.html`）只有两种模式，标题分别为 `Pair VPN Client` / `Pair VPN Server`：

- **Run as VPN Client** —— 本机是连接方，流量经隧道送到「配对过的服务端设备」
- **Run as VPN Server** —— 本机把自身网络共享给配对进来的客户端（最多 **10** 台）

客户端面板实测元素（截图 `shots/14_client.png` / `s2.xml`）：

```
Connect VPN          [toggle]      连接所选的服务器设备
Select Server        (New Server)  ← 只有一个「新建配对」入口，没有任何列表
Authenticate User    [toggle]
Ping Host
Network Discovery
```

服务端相关文案（native 字符串）：

```
PairVPN server can only pair with a maximum of 10 client devices.
PairVPN server can only pair with a maximum of 10 client devices. Please remove an existing pairing before adding new one.
```

配对码有效期 10 分钟（`Pairing code expires in %02d:%02d`，UI 文案 `Pairing code expires in 10:00`）。

## 3. 控制面协议（地址服务器）

### 3.1 端点来源（可复现）

在 `libnative-lib.so` 中定位格式串 `https://%s/dev/%s?%s`（VA `0x7cfbb`），扫描 ARM64 的 `ADRP+ADD` 引用（`tools/find_url_refs.py`），得到引用点 `0xb27b8`，紧邻的下一条就是 host 常量：

```
0xb2760 add -> 'rand=%d&ver=%d&os=%s&osver=%d&code=%s&%s'
0xb27b8 add -> 'https://%s/dev/%s?%s'
0xb27bc add -> 'pairv.net'          ← host
0xb2d9c ldr -> 'iceId=%s&pairCode=%s&flags=%d&svrName=%s&hwId=%s'
```

⇒ **地址服务器 = `https://pairv.net/dev/<action>?<params>`**（`pairv.net` → `45.33.111.235`，Linode）

### 3.2 三个 action

| action | 用途 | 参数模板 |
| --- | --- | --- |
| `client_pairing` | 客户端凭 6 位配对码换取会话 | `rand=%d&ver=%d&os=%s&osver=%d&code=%s&%s` |
| `server_pairing` | 服务端注册自身 ICE 地址 | `iceId=%s&pairCode=%s&flags=%d&svrName=%s&hwId=%s` |
| `remove_pairing` | 注销配对 | 同 client，`code` 为目标配对 |

另有配对校验参数串（native）：

```
seq=%d&deviceId=%s&pairId=%s&key=%s&flags=%d&rs=%d&carrier=%s&model=%s
seq=%d&pairId=%d&key=%s
seq=%d&pairId=%d&key=%s&deviceId=%s&carrier=%s&model=%s
```

### 3.3 响应格式（**实测**）

```
HTTP/1.1 200 OK
（空行）
<64 个字符的不透明令牌>
```

实测样本（`tools/probe_addrserver.py probe`，2026-10-28）：

```
client_pairing  -> i7-cgkq.IfnWdcNN-ZZGCJD3DrI58zzKABon7m5Tu-4HsYDcfrQyaKmz0EAnA0I7
server_pairing  -> AwfyxuchYbwQHegLERxMCSmhYV74IRZOcriCEctW4c1Y6TqcTZYe9Wk0T.B8.5Ac
remove_pairing  -> Fgjn.n0tUeJ4ZPM-oi4368nRuUwhQipSHTdL1SFTu7g5Zp-s4yv8jnB7KjvXfAZY
```

关键观察（容易被误判成「三段结构」）：

- 长度恒为 **64**；
- `.` 出现的位置每次随机（`IHP..06IUX…`、`C9J9amYmLHpHYdrk.e.JypINRHyL9e6M6.…`），**说明 `.` 是字符表成员，不是分隔符**；
- 字符表 = `[A-Za-z0-9-_.]`（65 个字符，≈385 bit 熵）。

**未注册的配对码不报错**：`code=123456` / `code=` 空 / 完全不传参，均返回 200 + 一个新的 64 字符令牌。失败是延后到 ICE/握手阶段才暴露的（native 里的 `Corrupted data from address server` / `Relay handshake failed. %s`）。

### 3.4 连通性压测（第一轮，只读）

`tools/probe_addrserver.py bench -n 24 -c 4`：

```json
{
  "action": "client_pairing", "requests": 24, "concurrency": 4,
  "wall_s": 13.92, "success": 24, "success_rate": 100.0, "rps": 1.72,
  "p50_ms": 1855.0, "p95_ms": 2871.1, "max_ms": 3929.3,
  "resp_len_values": [64], "errors": []
}
```

→ 会话发放层稳定（100% 成功率），但延迟不低（P50 ≈ 1.85 s，跨太平洋 + TLS 握手），**单实例吞吐也只有 ~2 rps 量级** —— 即使有节点，这一层也不适合高频调度。

## 4. 数据面：直连 → 打洞 → 中继

native 中的状态机字符串完整还原了连接路径：

```
Verifying NAT...
Symmetric NAT-port, relay needed unless peer has no NAT
Direct connecting to VPN server...
Failed to reach VPN server, trying relay...
Connecting to relay server...
Handshaking with relay server...
Relay handshake failed. %s
relayed-%02d%d
```

隧道内部地址（UI 模板）：

```
Client: 192.128.11.12
Server: 192.128.11.1 (pvhost)
```

> ⚠️ `main.html:263-264` 里的 `192.128.11.12` / `68.24.126.88` 是**静态占位文案**，不是真实运行值。实测 `ip addr` 无 tun 接口、`ss` 无到 `68.24.126.88` 的连接，已核对排除。

会话字段（native）：

```
sessionKey            session_hardware_id     session_tunnel_server_ip
session_cli_ice_server_address                session_peer_flags
session_offer_permission  session_offer_mask  session_plain
session_last_svr_pairid   session_last_svr_status
```

`session_cli_ice_server_address` 说明：**ICE 服务器地址是服务端设备注册上来的**（`server_pairing?iceId=…`），不是公共服务清单。这正是「没有节点池」的结构性原因——地址由对端提供，不来自厂商。

## 5. 其它发现

| 项 | 结果 |
| --- | --- |
| Firebase 项目 | `pairvpn-5fdd7`（`google-services` 里的 `project_id` / `firebase_database_url` / `google_storage_bucket`） |
| RTDB 匿名读 | `https://pairvpn-5fdd7.firebaseio.com/.json` → **401 Permission denied**（不可匿名枚举，✔ 安全） |
| 阻断/探测域名 | `v0cdn.net`、`nsatc.net`、`msftncsi.com`、`windowsupdate.com`、`ntservicepack.microsoft.com`、`8.8.8.8`、`224.0.0.251`(mDNS)、`169.254.0.0/16` —— 属于 `IpHandler::IsBlockedWindowsDns` 与连通性探测 |
| 权限模型 | `lan` / `lancast` / `all`（`pref_svr_permission`），对应文案 `Allow whitelisted IPs Only` / `Local Network with Discovery` |
| 加壳/反调试 | `classes3.dex` 含 `ApkSignatureKillerEx`（反签名校验）；`El-a Mo-ds.so` 为 ElaMods 注入物 |
| 跨应用推广 | 实测该改包会拉起其它 mod 应用（`com.alohamobile.vpn`、`shuttlevpn` 等），干扰 UI 自动化，需 `pm disable-user` 隔离 |

## 6. 复现方式

```bash
# 0. 解包
unzip -o "PairVPN com.pairvpn v1.8.51 b1851.apk" -d raw
java -jar apktool.jar d -f -s -o apktool_out "../PairVPN com.pairvpn v1.8.51 b1851.apk"
jadx -d jadx_out "../PairVPN com.pairvpn v1.8.51 b1851.apk"

# 1. 字符串
node -e '...'   # 见 tools 说明；或直接用 rg 在 raw/classes*.dex + lib/*/libnative-lib.so 上扫

# 2. 定位 URL 常量（自写 ARM64 ADRP+ADD 扫描器，不依赖 capstone）
python tools/find_url_refs.py "https://%s/dev/%s?%s"
python tools/find_url_refs.py "pairv.net"

# 3. 线上探活 / 压测
python tools/probe_addrserver.py probe
python tools/probe_addrserver.py bench -n 24 -c 4

# 4. demo
python demo/server.py --port 8912   # 打开 http://127.0.0.1:8912/
python tools/mock_addrserver.py --port 8911   # 纯离线协议 mock
```

## 8. 判断

这个 App 的协议设计是**干净的**：无服务器列表、无匿名可用凭证、RTDB 关闭、配对码 10 分钟过期、单服务端限 10 客户端。
它没有任何可用于代理池的「公共出口」，所有出口都是用户自己的设备。
